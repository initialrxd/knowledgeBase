# 多知识库管理台

在项目根目录运行 `scripts\Start-Manager.ps1 -Background`，浏览器将通过一次性登录链接打开管理台。
默认地址为 http://127.0.0.1:8767。也可使用 `.env` 中的管理员令牌登录。
`scripts\Start-All.ps1` 同时启动管理台和 Open WebUI，`scripts\Stop-All.ps1` 正常保存检查点后停止服务。

CMD 使用 `scripts\Start-Manager.cmd --background`；全部启动和停止分别为
`scripts\Start-All.cmd`、`scripts\Stop-All.cmd`。可添加 `--no-browser`，自定义端口使用 `--port 端口号`。

## 使用流程

1. 在“Embedding 配置”新增或编辑 API 地址、模型及密钥，点击“测试”。模型须支持 OpenAI 兼容的 `/embeddings` 请求。
2. 在“知识库”创建独立知识库，填写数据源目录及向量化存储目录，并选择 Embedding 配置；两个位置均为必填，不能重叠。数据源可每行填写一个目录。
3. 系统保存来源设置，首次启动后自动扫描与监听 PDF。向量保存在所选存储目录的 `vectors/`，切片及元数据保存在同一存储根目录；不自动启动时，来源设置仍会保留。之后也可在“来源目录”增删目录。
4. 在“任务记录”按文件名查看提取和向量化进度，悬停文件名可查看来源路径。详情显示页数、切片进度和失败原因；历史任务也按原文件名展示，不需要重新导入。失败任务可重试；暂停只阻止后续任务，已发布内容仍可检索。
5. 在“MCP 服务”创建入口，选择一个或多个知识库，设置端口及令牌。令牌留空时自动生成。
6. 启动 MCP，点击“测试”验证协议初始化和工具列表，再通过“客户端配置”复制带令牌的连接配置。服务运行时也可编辑名称、端口、关联库及令牌；点击“保存并重启”自动应用，失败恢复原配置。

## 检索测试耗时

在知识库的“检索配置”下，可用当前草稿参数连续测试 2–10 次（默认 5 次），无需保存。
各次顺序执行，包含首次请求；全部成功后显示算术平均值、每次耗时明细及最后一次检索结果。
中途失败时不显示本轮平均值，重新测试会清除上一轮结果。

| 项目 | 计时范围 |
| --- | --- |
| 总耗时 | 浏览器发送请求至完成响应解析 |
| 服务端处理（汇总） | 以下服务端内部阶段之和，仅作汇总，不重复相加 |
| 问题向量化 | Embedding 调用，含等待、重试和响应校验 |
| 关键词检索 | 查询分词、全文查询和关键词排名 |
| 向量检索 | 分类候选过滤与向量查询，含数据库锁等待 |
| 结果整理 | 有效片段读取、排名融合、排序、去重和引用生成 |
| 服务端其他处理 | 参数准备、模型配置读取、资源清理等剩余处理 |
| 请求额外开销 | 总耗时减去服务端处理，含管理台转发、传输、序列化和浏览器解析，最小为零；不代表纯网络延迟 |

平均值使用原始精度计算，以毫秒显示一位小数。阶段未执行时显示“未执行”；部分请求跳过时，
该次按零计入整轮平均并标明跳过次数。旧服务未提供的计时显示“不可用”，不推算缺失值。
混合检索向量化失败后若成功降级为关键词检索，会保留失败尝试耗时和警告。
手机端可横向滚动“查看每次耗时”中的表格。

单库 `/v1/search` 成功响应新增 `timings_ms`：`total_ms`、`embedding_ms`、`keyword_ms`、
`vector_ms`、`results_ms`、`other_ms`，单位均为毫秒；未执行的阶段为 `null`。
管理台检索测试接口直接透传该字段。多库聚合检索不汇总各库计时。

## 状态解释

| 信息 | 含义 |
| --- | --- |
| 运行中 | 对应 worker 或 MCP 监听器存活 |
| 已完成 | 当前有效文档已被当前 Embedding profile 索引，没有待处理索引任务 |
| 待重建 | 当前配置与已发布索引的 profile 不同 |
| Ready | 索引完整、来源扫描完成且最近 Embedding 探测成功 |
| 降级可用 | 有已发布内容，但连接、扫描或索引状态存在问题；可尝试关键词检索 |
| 未验证 | 索引完整，但尚未确认连接或检测结果已过期 |

总体状态使用完整队列统计，而非仅依据页面展示的最近 50 条任务。
导出和离线 benchmark 不会单独阻塞检索 Ready 状态。
正在使用的 Embedding 配置每五分钟探测一次，共享同一配置的知识库不会重复探测；探测发送一条短文本。

## 数据、凭据与兼容

- 现有数据原地登记为默认库，保留原索引及 8765 管理 API、8766 查询/MCP 接口。
- 新建知识库时明确选择向量化存储根目录，须为空目录或尚未创建的目录；资料来源始终单独指定。
- 管理定义在 `manager-data/manager.sqlite3`，凭据在独立的 `manager-data/secrets.json`，运行日志在其 `logs/` 子目录。
- `manager-data/` 含真实凭据，只能作为本机敏感配置处理，不应提交、分享或并入知识库迁移包。
- 首次接管后，Embedding 配置以管理台为准。默认库配置同步到 `.env`，使单独启动的旧服务也能使用相同配置。
- 聊天和分类模型的地址、密钥、模型名及回答预算以全局 `.env` 为准。修改后重启管理台，所有库会读取新配置；遗留的旧 worker 会先正常停止再重新启动，不会直接复用旧模型设置。库级调优、共享 Embedding 配置和访问令牌保持独立。
- 更换模型、地址、维度或 Revision 后，点击“重建索引”；新索引完整后才切换，失败继续保留旧索引。
- 仅更换 API Key 不改变向量 profile。编辑共享配置会先正常停止受影响的运行中 worker，再应用配置并重启。
- 移除来源只停止同步；移除知识库只解除管理，保留磁盘数据。须先解除 MCP 关联，默认库保留用于兼容。
- 多库结果包含 `knowledge_base_id` 与库名称，读取文档或片段时传回该 ID；每个 MCP 的令牌只允许访问其绑定的库。
- 跨库排名按各库内的名次融合，各库使用自己的模型生成查询向量。部分库失败时返回可用结果及警告。

## 任务与索引恢复

- 相同参数的排队或运行任务会合并；已完成任务再次执行时创建新记录，保留历史。扫描发现的失败入库任务仍需显式重试，避免反复调用失败的模型接口。
- 首次运行新版时自动将元数据库升级到版本 2，仅调整任务队列的去重规则，保留任务 ID、状态、进度与历史。迁移包格式仍为版本 1，可以继续恢复原有导出包；旧版程序不支持直接打开版本 2 的元数据库。
- 未发布或已过期版本的向量在取候选结果前排除，因此中途失败的大文档不会挤掉已发布内容。
- 重建索引会核对实际切片向量，修复旧版本遗留的失效完成标记；已有 embedding 缓存可复用，无需再次请求相同模型下的相同文本。
- 内容相同的来源仍去重；其中一份更新而其他副本仍存在时，会分成独立文档，分别保留和检索。正常重命名继续沿用原文档记录。

## 排查与构建

- 端口占用：换用未占用的 MCP 端口。运行中保存配置会自动重启 MCP；新端口绑定失败会恢复原配置与监听器。端口或令牌变化后重新复制客户端配置。
- worker 启动失败：检查 `manager-data/logs/<knowledge_base_id>.log`；数据目录只能由一个服务写入。
- 停止较慢：当前提取或 Embedding 批次正在保存检查点，不会直接强制结束进程。
- 无法连接模型：检查 Base URL 是否包含所需 `/v1`，模型名称、密钥、网络和维度是否匹配。
- 登录链接失效：重新运行启动脚本获取新的链接，或用管理员令牌登录。

前端源码在 `frontend/`，修改后执行 `npm ci` 和 `npm run build`，产物由 FastAPI 直接提供；生产使用不需要 Node 开发服务器。
管理台仅监听本机，不提供第三方通用 MCP 程序管理、局域网多人权限或桌面安装包。
